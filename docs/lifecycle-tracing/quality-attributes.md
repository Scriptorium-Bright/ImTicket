# 예약·결제 생명주기 추적 품질속성 기준

작성일: 2026-09-20(KST)

관련 문서: [문서 지도](README.md) · [요구사항](requirements.md) · [C4 아키텍처](c4-architecture.md) · [SLI·SLO 기준선](sli-slo-baseline.md)

## 1. 목적

이 문서는 생명주기 추적 기능의 품질속성을 시험 가능한 시나리오로 고정한다. 각 시나리오는 자극 원천, 자극, 환경, 대상, 시스템 응답과 응답 측정값을 포함한다.

프로젝트 전체 품질 모델은 [ISO/IEC 25010 품질 특성 적용 현황과 달성 목표](../2026-08/architecture/iso-iec-25010-quality-status-and-targets.md)를 따른다. 이 문서는 예약·결제 생명주기 추적에 직접 영향을 주는 기능적 적합성, 신뢰성, 성능 효율성, 유지보수성, 보안성, 호환성과 유연성에 범위를 한정한다.

## 2. 품질 우선순위

| 우선순위 | 품질속성 | 선택 이유 |
| ---: | --- | --- |
| 1 | 기능적 적합성·데이터 무결성 | 커밋된 상태와 사건이 일치하고 동일한 최종 상태의 실행 경로를 정확히 설명해야 한다. |
| 2 | 신뢰성 | 중복·순서 역전·지연·프로세스 중단 뒤에도 같은 결과로 수렴해야 한다. |
| 3 | 성능 효율성 | 사건 기록과 처리가 기존 예약·결제 트랜잭션의 지연과 잠금 경합을 허용 범위 안에 유지해야 한다. |
| 4 | 유지보수성 | 사건 계약과 재구성 규칙을 독립적으로 시험하고 조회 모델을 재처리할 수 있어야 한다. |
| 5 | 보안성 | 결제·예약 식별자와 상태 이력의 접근을 통제하고 민감정보 수집을 제한해야 한다. |
| 6 | 호환성·유연성 | 기존 Spring·MySQL·관측 구성과 함께 동작하고 측정 근거가 생기면 전달 기술을 교체할 수 있어야 한다. |

정확성 SLO는 처리 지연 목표보다 높은 우선순위를 가진다. 처리량을 높이는 변경도 누락 0건, 중복 적용 0건과 최종 상태 일치율 100%를 유지해야 한다.

## 3. 품질속성 시나리오

### QA-01. 커밋 사건의 원자성

| 요소 | 기준 |
| --- | --- |
| 품질속성 | 기능적 적합성 / 기능 정확성, 데이터 무결성 |
| 자극 원천 | 예약·결제·만료 업무 서비스 |
| 자극 | 업무 상태와 생명주기 사건을 생성하는 트랜잭션이 커밋 또는 롤백됨 |
| 환경 | 정상 처리, 예외 발생, 데이터베이스 제약 위반 |
| 대상 | 업무 원장과 `lifecycle_event` |
| 응답 | 커밋 시 상태와 사건이 함께 존재하고 롤백 시 둘 다 남지 않음 |
| 응답 측정값 | 커밋 사건 누락 0건, 롤백 사건 0건 |
| 검증 | 서비스 통합 시험, Testcontainers MySQL, 기존 정합성 회귀 시험 |

| QG-4 | 조회 기능 완료 | QA-08, QA-10 | 단일 조회·완전성·권한·데이터 최소화 기준 통과 |
| QG-5 | 초기 운영 승인 | QA-06, QA-07, QA-11 | 확정된 지연·용량 SLO 통과, 다중 인스턴스 실행 규칙과 대응 절차 확인 |

## 6. 변경 원칙

- 사건 종류나 필수 필드를 바꾸면 `requirements.md`의 계약과 QA-09 호환성 시험을 함께 갱신한다.
- 트랜잭션 경계, 순서 규칙, 저장소 또는 전달 기술을 바꾸면 ADR과 C4를 함께 갱신한다.
- 품질 목표값을 바꾸면 원시 측정 결과, 실행 조건과 변경 이유를 SLI·SLO 문서에 연결한다.
- 품질 게이트를 통과하지 못한 변경은 해당 Phase의 완료로 기록하지 않는다.
- 통제된 시험 결과와 운영 측정값은 구분해서 보고한다.
